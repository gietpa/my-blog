지난 24시간 동안 이 저장소에서 실제로 일어난 일을 근거로 블로그 글 초안을 하나 작성한다.

## 1. 재료 모으기

먼저 실행한다:

```bash
node scripts/daily-brief.js
```

**종료 코드가 1이면 (커밋 없음) 여기서 멈춘다.** 파일을 만들지 말고, 쓸 거리가 없었다고만 보고한다. 활동이 없는 날 글을 지어내는 것이 이 명령어가 막으려는 바로 그 실패다.

커밋이 있으면, 실제로 무엇이 바뀌었는지 이해할 만큼 `git show`나 `git diff`로 파고든다. 커밋 제목만 보고 쓰지 않는다 — 제목은 무엇을 했는지는 말해도 왜 했는지는 말해주지 않는다.

## 2. 글 쓰기

`posts/YYYY-MM-DD-<영문-slug>.md`에 작성한다. frontmatter는:

```yaml
---
title: "제목"
date: "YYYY-MM-DD"
tags: [...]
description: "한 줄 요약"
draft: true
---
```

`draft: true`는 **반드시 넣는다.** 빌드에서 제외되므로, 사람이 읽고 고친 뒤 이 줄을 지워야 공개된다. 검토 없이 발행되지 않게 하는 장치다.

내용 규칙:

- **커밋에 실제로 있는 것만 쓴다.** 배우지 않은 교훈이나 겪지 않은 어려움을 지어내지 않는다. diff에서 근거를 댈 수 없는 문장은 빼라.
- **무엇을 했는지가 아니라 왜 그렇게 했는지를 쓴다.** "CSS 변수를 추가했다"는 커밋 로그로 충분하다. 글에는 왜 그 방법을 골랐고 무엇을 포기했는지가 들어가야 한다.
- 실제 커밋에 근거가 있을 때만 코드 예시를 넣고, 코드 펜스에는 언어를 명시한다 (```js).
- 본문에 제목을 `# H1`으로 반복하지 않는다. 템플릿이 frontmatter의 title로 이미 렌더링한다.
- 기존 글([posts/](../../posts/))의 문체를 따른다. 한국어, 담백하게, 과장 없이.
- 그날 한 일이 사소하면 사소한 대로 짧게 쓴다. 별것 아닌 변경을 대단한 통찰인 척 부풀리지 않는다.

## 3. 보고

작성한 파일 경로, 무엇을 근거로 삼았는지, 그리고 발행하려면 `draft: true`를 지우고 `npm run build`를 실행하면 된다는 것을 알린다.
