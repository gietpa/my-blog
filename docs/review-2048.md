### 2.4 입력과 접근성

- 보드 포커스 시 방향키 `preventDefault` 적용 → 페이지가 스크롤되지 않음.
- 게임이 쓰지 않는 키(`PageDown`)는 `preventDefault`되지 않음 → 보드에 포커스가 있어도 페이지 탐색이 살아 있다.
- `aria-live` 영역이 **정확히 1개** → 중복 낭독 없음.
- `#game-status`가 시각적으로 숨겨짐(높이 1px). 저장소에 `visually-hidden` 유틸리티가 없어 id로 직접 처리했다.
- 보드 `touch-action: none` (`game-2048.css:74`) → 모바일 스와이프가 페이지 스크롤에 먹히지 않는다.
- `localStorage` 읽기·쓰기 모두 `try/catch`.
- 탭 순서: `My Blog` → `2048` → 테마 토글 → `New Game` → 보드. 합리적이다.

### 2.6 코드로 확인한 항목 (측정 아님)

- **`prefers-reduced-motion`**: `game-2048.css:224`에서 `.tile--new`, `.tile--merged`의 `animation: none`. 규칙은 올바르다.
- **no-JS 폴백**: 보드·점수판·버튼·도움말이 기본 `display: none`이고 `.js`가 붙을 때만 표시된다. `.game__nojs`는 `.js`일 때 숨는다. `layout.css`의 기존 `.theme-toggle` 패턴과 동일하다. 죽은 격자 대신 문장이 나오는 구조가 맞다.

## 3. 발견 사항

### 3.1 `role="row"` 누락 — 사소 · **해결됨 (2026-08-15)**

> 수정 완료. `.board__row` 래퍼 4개에 `role="row"`를 주고 `display: contents`로 레이아웃에서 제거했다.
> 확인: 마크업에 `[role="row"]` 4개 / `[role="gridcell"]` 16개, 브라우저 실측으로 시각적 행 4 × 열 4 유지,
> UI가 찾는 셀 16개 그대로, 이동·타일 생성 정상, 코어 테스트 26/26.
> 아래는 원래 발견 내용이다.

`scripts/lib/templates.js:141-144` / 렌더된 마크업

보드는 `role="grid"`이고 셀 16개가 `role="gridcell"`인데, 그 사이 `role="row"` 계층이 없다(실측: `[role="row"]` 0개, `[role="gridcell"]` 16개).
ARIA 명세는 `grid` → `row` → `gridcell` 계층을 요구하므로, 엄밀히는 부적합이다.

**spec 내부의 모순이다.** §7은 행에 `role="row"`를 요구하지만 §8의 DOM 계약은 셀을 보드 직속 자식으로 두며, 후자는
`display: grid`가 요구하는 구조다. 에이전트 A가 이를 발견하고 임의로 고치지 않은 채 보고했다 — 지침대로 옳은 판단이다.

실질적 영향은 크지 않다. 이 게임에서 격자 구조 자체는 정보가 아니고(칸의 좌표를 읽을 이유가 없다), 상태는
`#game-status` 라이브 영역으로 전달되며 그쪽이 정상 동작한다.

**권고:** 고친다면 행 래퍼 `<div role="row">` 4개에 `display: contents`를 주면 레이아웃을 유지한 채 계층을 맞출 수 있다.
급하지 않다. 고칠 경우 templates.js(A 영역)와 game-2048.css(C 영역)를 함께 건드려야 한다.

## 4. 검증하지 못한 항목

**이 절이 이 문서에서 가장 중요하다. 아래는 확인되지 않았다.**

1. **승리(2048 타일) 오버레이** — 2048에 도달시키지 못해 승리 경로를 실행하지 못했다. `Keep going` 버튼이 존재하고 게임 오버 시 올바르게 숨겨지는 것까지만 확인했다. 승리 오버레이가 실제로 뜨는지, "계속하기" 후 승리 판정이 다시 뜨지 않는지는 **미확인**이다.
2. **좁은 화면 실측** — `resize_window`가 성공을 반환했으나 뷰포트가 1512px에서 바뀌지 않아 375px 실측에 실패했다. §2.6은 CSS 규칙에 근거한 추론이며 측정이 아니다.
3. **`prefers-reduced-motion` 실동작** — CSS 규칙만 확인했다. 실제로 애니메이션이 멈추는지 에뮬레이션으로 확인하지 못했다.
4. **프라이빗 브라우징 / 실제 스크린 리더** — `localStorage` 예외 경로와 VoiceOver 낭독은 실행하지 못했다. `try/catch` 존재와 라이브 영역 1개는 코드·DOM으로 확인했다.
5. **실제 터치 기기 스와이프** — `touch-action: none`과 핸들러 존재는 확인했으나 실기기 테스트는 하지 못했다.

무한 개선 루프가 열렸다. 2차 지침에 "두 번 조정해도 안 되면 실측값과 함께 미달로 보고하라"를 넣자 파일은 나왔다.
