# 지침 B: 2048 코어 로직 + 테스트

## 역할

Work 단계 서브에이전트 **B**. 게임의 순수 로직과 그것을 검증하는 테스트를 만든다.
**DOM도 CSS도 네 일이 아니다.** 브라우저를 열 필요 없이 완결되는 작업이다.

설계는 [`docs/spec-2048.md`](../spec-2048.md)에 확정되어 있다. **먼저 정독하라.** 특히 §2(게임 규칙), §3(알고리즘), §8 "계약 2 — 코어 API", §9.1(테스트).
spec과 이 지침이 어긋나면 spec이 우선이다.

## 수정 허용 범위

**이 세 파일만:**

- `assets/js/game-2048-core.js` (신규)
- `scripts/test-2048.js` (신규)
- `package.json` (`"test:2048": "node scripts/test-2048.js"` 스크립트 **추가만**. 의존성은 건드리지 마라.)

다른 파일은 만들지도 고치지도 않는다. 다음은 **다른 에이전트가 동시에 작업 중**이다:

- `scripts/build.js`, `scripts/lib/templates.js` (에이전트 A)
- `assets/js/game-2048-ui.js`, `assets/css/*` (에이전트 C)

## 코어 설계

### 형태

브라우저 전역 IIFE로 `window.Game2048Core`에 붙인다. ES 모듈을 쓰지 않는다 — 이 프로젝트에는 번들러가 없고, 기존 `assets/js/theme-toggle.js`가 같은 스타일이다. **먼저 그 파일을 읽고 코드 스타일을 맞춰라.**

### API (계약 — 에이전트 C가 이 이름으로 호출한다. 바꾸지 마라)

```
createGame(rng?)         → state
move(state, direction)   → { moved, state, gained, merged[], spawn }
collapseLine(line)       → { line, gained, mergedSlots }
hasMoves(grid)           → boolean
isWon(grid)              → boolean
```

- **`move`는 순수 함수다.** 인자로 받은 `state`를 변형하지 않고 새 객체를 돌려준다.
- `rng`는 주입 가능해야 한다(기본 `Math.random`). 테스트 결정성을 위한 것이며, 이게 없으면 새 타일 생성을 검증할 수 없다.
- `direction`은 `'left' | 'right' | 'up' | 'down'`.

### 반드시 지킬 규칙

1. **이중 병합 금지.** 한 번의 이동에서 이미 병합된 타일은 다시 병합되지 않는다. `[2,2,4]` → `[4,4,0,0]`이지 `[8,0,0,0]`이 아니다. spec §3.2의 `i += 2` 방식을 쓰라 — `merged` 불린 배열을 관리하는 흔한 구현보다 상태가 적어 틀릴 여지가 작다.
2. **스캔 순서는 미는 벽에 가까운 쪽부터.** `[2,2,2]`를 왼쪽으로 밀면 `[4,2,0,0]`이지 `[2,4,0,0]`이 아니다.
3. **4방향을 각각 구현하지 마라.** `collapseLine` 하나 + 방향별 인덱스 순서(spec §3.1). 격자 회전도 쓰지 마라 — 병합 위치를 UI에 돌려주려면 회전을 역산해야 해서 좌표 버그가 생긴다.
4. **격자가 실제로 바뀌지 않았으면 새 타일을 만들지 않고 점수도 안 올린다.** 벽에 막혔는데 타일이 생기면 플레이어는 손해 없이 패배한다.
5. **패배 판정은 "빈 칸 없음 AND 인접한 같은 값 쌍 없음".** 빈 칸만 보면 꽉 찼지만 합칠 수 있는 판을 패배로 오판한다.
6. 새 타일 값은 2가 90%, 4가 10%. 빈 칸 중 균등 확률.

코어는 `document`, `window`, `localStorage`를 **몰라야 한다.** 전역에 자기 자신을 붙이는 것 외에 브라우저 API를 쓰지 마라. 그래야 Node에서 테스트된다.

## 테스트

`node scripts/test-2048.js`로 실행된다. `node:test` + `node:assert`만 쓴다. **npm 의존성을 추가하지 마라** — 이 프로젝트의 핵심 제약이고 `scripts/serve.js`가 선례다.

코어가 브라우저 IIFE라 Node에서 import할 수 없다. `node:fs`로 파일을 읽고 `node:vm` 컨텍스트에서 실행해 `Game2048Core`를 꺼내라. 이 방식이면 프로덕션 파일에 테스트 전용 export 분기를 넣지 않아도 된다 — **넣지 마라.**

최소 검증 항목(spec §9.1):

- `collapseLine` — spec §3.2 표의 6케이스 **전부**. 특히 `[2,2,4,0] → [4,4,0,0]`과 `[4,4,4,4] → [8,8,0,0]`.
- `move` — 비대칭 고정 격자로 4방향 각각 스냅샷 비교. 방향별 인덱스 매핑 오류가 여기서 잡힌다.
- 변화 없는 이동에서 `moved === false`이고 **새 타일이 생기지 않는다.**
- 점수 누적이 병합 값의 합과 일치한다.
- `hasMoves` — 꽉 찼지만 인접 동일 쌍이 있으면 `true`, 완전 교대 격자면 `false`.
- `isWon` — 2048 타일 생성 시점.
- 시드 고정 `rng`로 새 타일이 빈 칸에만, 2 또는 4로만 생긴다.
- `move`가 인자 `state`를 변형하지 않는다(순수성).

테스트는 **반드시 실제로 실행해서 통과시켜라.** 작성만 하고 돌리지 않는 것은 완료가 아니다.
