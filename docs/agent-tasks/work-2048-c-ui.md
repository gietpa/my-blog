# 지침 C: 2048 UI + 스타일

## 역할

Work 단계 서브에이전트 **C**. 게임을 화면에 그리고 입력을 받는다.
**게임 규칙 로직은 네 일이 아니다** — 에이전트 B가 만드는 코어를 호출만 한다. **HTML 마크업도 네 일이 아니다** — 에이전트 A가 템플릿에서 생성한다.

설계는 [`docs/spec-2048.md`](../spec-2048.md)에 확정되어 있다. **먼저 정독하라.** 특히 §5(입력), §6(렌더링·색상 토큰), §7(접근성), §8의 계약 2개.
spec과 이 지침이 어긋나면 spec이 우선이다.

## 수정 허용 범위

**이 세 파일만:**

- `assets/js/game-2048-ui.js` (신규)
- `assets/css/game-2048.css` (신규)
- `assets/css/variables.css` (타일 색 토큰 **추가만**. 기존 토큰 값은 바꾸지 마라.)

다른 파일은 만들지도 고치지도 않는다. 다음은 **다른 에이전트가 동시에 작업 중**이다:

- `scripts/lib/templates.js`, `scripts/build.js` (에이전트 A — DOM 마크업 담당)
- `assets/js/game-2048-core.js`, `scripts/test-2048.js`, `package.json` (에이전트 B)

**A와 B의 작업은 이미 끝났다. 추측하지 말고 실물을 읽어라.**

- **마크업 실물**: `dist/games/2048/index.html` — A가 생성한 실제 HTML이다. 요소 id·클래스·`aria` 속성이 전부 여기 있다. 이걸 읽고 맞춰라.
- **코어 실물**: `assets/js/game-2048-core.js` — B가 만든 실제 코드다. 함수 시그니처와 반환 형태를 여기서 확인하라.

B가 알려온 사항(코어 실물에서 재확인하라):

- 격자는 **평탄한 16칸 배열**이다. `index = row * 4 + col`, `0`은 빈 칸.
- `state` = `{ size, grid, score, won, over, rng }`. `won`/`over`는 미리 계산되어 있으니 UI가 다시 판정하지 마라.
- `move`의 `merged[]`와 `spawn`은 `{ index, row, col, value }` 형태다. `spawn`은 아무것도 안 생기면 `null`.
- 막힌 이동에서는 `{ moved: false, state: <같은 객체> }`가 온다. `if (!result.moved) return;`이 안전하다.
- 알 수 없는 방향 문자열은 **예외를 던진다.**

A가 남긴 주의사항:

- `#game-over` 오버레이는 **비어 있다.** 승리/패배 UI를 네가 채워야 한다. `hidden` 속성을 토글하라(`display: flex`를 쓴다면 `[hidden] { display: none }`로 막아라).
- 저장소에 `visually-hidden` 유틸리티 클래스가 **없다.** `#game-status`를 id로 직접 숨기지 않으면 스크린 리더용 문구가 화면에 그대로 보인다.
- 승리/패배도 `#game-status` 한 곳으로만 알린다. 오버레이에 별도 라이브 영역을 만들지 마라 — 두 번 읽힌다.

## CSS

### 색상 — 가장 조심할 곳

**타일 색을 하드코딩하지 마라.** 이 프로젝트의 테마는 `variables.css`의 커스텀 프로퍼티 값만 바꿔서 구현된다.

`variables.css`를 **먼저 끝까지 읽어라.** 다크 토큰이 **두 곳**에 중복 선언되어 있다:

1. `[data-theme="dark"]` — JS가 동작할 때
2. `@media (prefers-color-scheme: dark) { :root:not([data-theme]) }` — JS가 꺼졌을 때 폴백

**두 곳 모두에 넣어야 한다.** 하나를 빠뜨리면 JS 꺼진 다크 모드에서만 색이 틀어지고, 평소 테스트로는 절대 발견되지 않는다.

spec §6의 **명도 램프 파라미터화**를 쓴다(사용자 승인 완료). 단계별 색을 전부 나열하지 마라. 램프면 다크 블록마다 4줄이면 끝나서 폴백 누락 위험이 크게 준다. 2048 특유의 베이지 → 주황 계열을 근사하도록 hue/saturation을 맞춰라.

### 대비 요구사항 — 여기서 시간을 쓰지 마라

이전 시도가 이 지점에서 갇혔다. 램프 하나로 라이트·다크 양쪽 끝에서 4.5:1을 동시에 만족시키는 값을 찾으려고 후보를 무한히 시험했다. **그렇게 하지 마라.**

지켜야 할 순서:

1. **먼저 세 파일을 다 만들어라.** 게임이 동작하는 것이 최우선이다. 색은 합리적인 초기값이면 된다.
2. 그 다음에 대비를 **한 번** 계산한다. 임시 Node 스크립트로 WCAG 상대 휘도를 계산해 라이트·다크 각각의 최저(2)·최고(2048) 단계를 검사하라. 손으로 반복 시험하지 마라.
3. 미달하면 **글자색 임계값을 조정해서** 해결하라 — 밝은 타일에는 어두운 글자, 어두운 타일에는 밝은 글자로 전환되는 단계 경계를 옮기는 것이 램프 자체를 다시 푸는 것보다 훨씬 쉽다.
4. **두 번 조정해도 4.5:1을 못 맞추면 거기서 멈추고, 실측값과 함께 미달로 보고하라.** 미달 보고는 실패가 아니다. 리뷰 단계에서 판단할 정보다. 완벽한 색을 찾느라 파일을 못 내놓는 것이 진짜 실패다.

계산 스크립트는 스크래치 디렉토리에 두고 저장소에 커밋될 파일로 만들지 마라.

### 레이아웃

- 보드는 `display: grid`, 셀은 `aspect-ratio: 1`로 정사각형 유지.
- 좁은 화면(375px)에서 보드가 잘리지 않아야 한다. 블로그는 모바일 우선 CSS다.
- **보드에 `touch-action: none`을 반드시 준다.** 없으면 스와이프가 페이지 스크롤과 함께 먹혀 휴대폰에서만 조작이 안 된다.
- `.game__nojs`는 `.js` 클래스가 없을 때만 보이게 한다. `layout.css:46-50`의 기존 패턴을 그대로 따르라.
- 애니메이션: `tile--new` scale-in, `tile--merged` pop, 각 약 120ms. **`@media (prefers-reduced-motion: reduce)`에서 둘 다 제거한다.**
- 타일 슬라이드 애니메이션은 **하지 않는다**(spec §10).

## JS

### 입력 (spec §5)

- 키 리스너는 `document`가 아니라 **보드 요소**에 건다. 보드는 마크업에서 이미 `tabindex="0"`이다.
- 로드 시 보드에 포커스를 준다. 클릭 없이 바로 플레이되게.
- `preventDefault()`는 **처리한 방향키에만.** 전역에서 방향키를 가로채면 게임 아래 설명 텍스트를 키보드로 읽을 수 없게 된다.
- `key`로 판정한다(`keyCode`는 폐기됨).
- 스와이프: `touchstart`/`touchend` 좌표 차이, 임계값 30px, 지배적 축 하나만. 임계값 미만은 탭으로 보고 무시한다.

### 상태와 저장

- 최고 점수는 `localStorage` 키 **`my-blog:2048:best`**.
- **읽기·쓰기를 `try/catch`로 감싼다.** 프라이빗 브라우징에서 예외가 난다. `assets/js/theme-toggle.js`의 기존 패턴을 읽고 맞춰라. 예외 시 최고 점수 기억만 포기하고 게임은 계속 동작해야 한다.
- 읽은 값은 `Number()` 후 유한한 0 이상 정수인지 검사한다(사용자가 손댈 수 있다).
- 진행 중인 판은 저장하지 않는다.

### 접근성 (spec §7)

- `#game-status`(`aria-live="polite"`)를 **이동이 실제로 일어났을 때만** 갱신한다. 벽에 막힌 입력에서는 조용히 있는다.
- **라이브 알림 지점은 한 곳뿐이어야 한다.** 점수 숫자에도 `aria-live`를 걸면 같은 내용이 두 번 읽힌다.
- 각 칸의 `aria-label`을 값 또는 `empty`로 갱신한다.
- 게임 종료 시 오버레이의 버튼으로 **포커스를 옮긴다.** 보드에 포커스가 남아 방향키가 안 먹으면 키보드 사용자가 갇힌다.
- 문구는 전부 **영어**(spec §7 결정 기록).

### 코드 스타일

`theme-toggle.js`를 읽고 맞춰라. 전역 IIFE, 프레임워크·라이브러리 없음. 이건 협상 대상이 아니다.

## 검증

A와 B가 끝났으므로 실제로 동작해야 한다.

1. `npm run build` → `dist/styles/game-2048.css`와 `dist/scripts/game-2048-ui.js`가 생기는지 확인.
2. `node scripts/test-2048.js`가 여전히 통과하는지 확인(네 작업이 코어를 건드리지 않았음을 확인하는 것이다).
3. 가능하면 `npm run serve` 후 `http://localhost:4321/games/2048/`를 열어 확인하라. 브라우저 도구가 없으면 최소한 생성된 HTML과 네 JS의 선택자가 맞는지 대조하라.
4. 브라우저로 확인하지 못한 항목은 **하지 못했다고 명시하라.** 추측으로 "동작 확인"이라고 쓰지 마라.

## 시간 관리

**막히면 부분 결과라도 파일로 남겨라.** 완성되지 않은 채로 아무것도 없는 것보다, 동작하는 기본형과 남은 문제 목록이 훨씬 낫다. 한 가지 세부사항(특히 색상값)을 완벽히 하려고 전체를 미루지 마라.

## 보고
