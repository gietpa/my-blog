블로그를 직접 만들어 보기 전까지 HTML, CSS, JavaScript는 그냥 "웹을 만들 때 쓰는 것들"이었다.
셋을 한 번에 굴려 보고 나니 각자 맡은 일이 꽤 뚜렷하게 갈린다는 걸 알게 됐다.

## HTML: 무엇인가

HTML은 내용이 **무엇인지** 말한다. 어떻게 보일지는 한 마디도 하지 않는다.

```html
<article class="post">
  <h1>오늘 배운 것</h1>
  <time datetime="2026-08-10">August 10, 2026</time>
</article>
```

여기서 `<time>`을 쓴 이유가 흥미로웠다. 그냥 `<span>`을 써도 화면에는 똑같이 보인다.
하지만 `<time datetime="...">`은 사람이 읽는 "August 10, 2026"과 기계가 읽는 "2026-08-10"을
같이 담는다. 검색 엔진이나 스크린 리더가 이걸 날짜로 이해할 수 있게 된다.

`<div>`로 다 만들 수 있지만 그러지 않는 이유가 여기 있었다.

## CSS: 어떻게 보이는가

CSS는 그 내용이 **어떻게 보일지**를 맡는다. 가장 인상 깊었던 건 커스텀 프로퍼티였다.

```css
:root {
  --color-bg: #ffffff;
  --color-text: #1a1a1a;
}

[data-theme="dark"] {
  --color-bg: #121212;
  --color-text: #e6e6e6;
}
```

다크 모드를 만들 때 색을 쓰는 규칙을 두 벌 쓸 필요가 없었다.
규칙은 그대로 두고 **값만 바꾸면** 됐다. `<html>`에 `data-theme="dark"`가 붙는 순간
그 변수를 쓰는 모든 곳이 한꺼번에 따라온다.

## JavaScript: 무엇이 일어나는가

JavaScript는 **동작**을 맡는다. 그런데 이 블로그에서 JavaScript가 하는 일은 놀랄 만큼 적다.
버튼을 눌렀을 때 테마를 바꾸고, 그 선택을 기억하는 것. 그게 전부다.

처음엔 버튼의 해/달 아이콘도 JavaScript로 바꿨는데, 결국 CSS로 옮겼다.

```css
.theme-toggle__icon::before { content: "☾"; }
[data-theme="dark"] .theme-toggle__icon::before { content: "☀"; }
```

아이콘이 어떻게 보이는지는 원래 CSS의 일이었다. JavaScript로 하면 페이지가 처음 그려질 때
잠깐 빈 버튼이 보이는데, CSS로 옮기니 그 문제가 그냥 사라졌다.
**제자리에 두면 문제가 저절로 없어지는 경험**이 재미있었다.

## 셋의 관계

세 줄로 정리하면 이렇다.

| 언어 | 맡는 일 | 없으면 |
| --- | --- | --- |
| HTML | 구조와 의미 | 페이지가 아예 없다 |
| CSS | 보이는 방식 | 못생겼지만 읽을 수는 있다 |
| JavaScript | 동작 | 정적이지만 여전히 쓸 수 있다 |

아래로 갈수록 없어도 괜찮아진다는 점이 핵심 같다.
실제로 이 블로그는 JavaScript를 꺼도 글을 읽는 데 아무 문제가 없다.
코드 색칠도 미리 입혀서 나오기 때문에 그대로 보인다.

각자 자기 일만 하게 두는 것. 오늘 배운 건 결국 이거였다.
